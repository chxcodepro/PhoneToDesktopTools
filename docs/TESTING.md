# 虚拟机 / 实机测试说明

用虚拟机测试 Win7 和银河麒麟（苹果系列除外）。手机要通过虚拟机的 **USB 直通** 连进虚拟机（VirtualBox 需要安装同版本的 Extension Pack，在「设备 → USB」里勾选手机；VMware 在「虚拟机 → 可移动设备」里连接）。

> 下面的网址请在能上网的电脑上下载，再拷进虚拟机。目标电脑本身不需要联网。

## 1. Windows 7 虚拟机

### 1.1 需要下载的文件

| 文件 | 网址 | 用途 |
|---|---|---|
| SHA-2 签名补丁 KB4474419 | https://www.catalog.update.microsoft.com/Search.aspx?q=KB4474419 | 没打这个补丁的 Win7 装不上新签名的驱动 |
| 服务堆栈更新 KB4490628 | https://www.catalog.update.microsoft.com/Search.aspx?q=KB4490628 | 安装上一个补丁的前置条件 |
| adb 33.0.3（项目内置的版本） | https://dl.google.com/android/repository/platform-tools_r33.0.3-windows.zip | 能在 Win7 上用的最新版本，见 1.5 |
| Google USB 驱动（备用） | https://dl.google.com/android/repository/usb_driver_r13-windows.zip | 电脑端界面里的「安装驱动」不能用时手动安装（见 1.3 第 2 步） |

补丁选择与虚拟机位数一致的版本（x64 或 x86）。

### 1.2 存放位置

在虚拟机里建一个文件夹，例如 `C:\p2d-test\`：

```
C:\p2d-test\
├── p2d-core.exe            ← 仓库 dist\core\windows-amd64\（32 位系统用 windows-386\）
└── vendor\
    ├── adb\                ← 解压 platform-tools 后，把其中的 adb.exe、AdbWinApi.dll、AdbWinUsbApi.dll 放这里
    └── app\
        └── p2d.apk         ← 手机端安装包（构建产物，见 docs/DEV.md）
```

### 1.3 测试步骤

1. 先装 KB4490628，重启；再装 KB4474419，重启。
2. 手机插上并直通到虚拟机。Win7 不会自动给手机装驱动：运行电脑端界面，它会显示「缺少驱动」，点「安装驱动」，
   在 UAC 窗口点「是」，提示「无法验证此驱动程序软件的发布者」时点「始终安装此驱动程序软件」。
   驱动是电脑端自带的驱动描述文件（只用系统自带的 WinUSB，所有品牌手机通用，没有微软签名所以会有这个提示）。
   备用的手动方法：在设备管理器里给「其他设备」下带黄色感叹号的手机（名字里带 ADB 的那个）
   右键「更新驱动程序软件」→「浏览计算机」→「从计算机的设备驱动程序列表中选择」→「从磁盘安装」，选 USB 驱动里的 `android_winusb.inf`，
   再选「Android ADB Interface」，提示不建议安装时选仍然安装。Google 驱动里没有写其他品牌手机的 ID（如一加 `VID_22D9`），所以要这样手动指定。
3. 双击运行 `p2d-core.exe`（会出现一个命令行窗口，显示运行日志）。
4. 看日志：
   - `发现设备 …（状态 unauthorized）`：在手机上点「允许 USB 调试」。
   - `正在安装 …`：部分手机需要在手机上确认安装。
   - `已启动手机端，等待连接` → `手机已连接`：说明自动连接成功。
5. 在手机上让 Agent 截图、读写文件、执行命令，并试试远程桌面。
6. 也可以测电脑端界面：仓库 `desktop/app/release/win-unpacked/` 整个文件夹拷进去，运行 `p2d.exe`（目前只打了 64 位）。把 adb 和 apk 放到 `resources\core\vendor\` 下，结构与上面一致。
7. 需要记录的结果：
   - adb 哪个版本能在 Win7 上运行；
   - 驱动是否安装成功；
   - 截图、键鼠在 Win7 上是否正常；
   - 界面红框在开启和关闭 Aero 两种情况下是否正常。

### 1.4 打包进安装包

手机端 APK 放到 `desktop/vendor/app/p2d.apk`，再运行 `npm run dist:win64`，它会被一起打进安装程序（见 desktop/vendor/README.md）。新版不再带 adb（见第 4 节）。

### 1.5 测试结果（2026年11月23日，Win7 旗舰版 SP1 x64 虚拟机，一加 13）

系统已打 KB4474419 / KB4490628，自带 UCRT（`ucrtbase.dll`）。没有 Aero（VMware 未开 3D，Win7 用的是 Basic 主题）。

| 项目 | 结果 |
|---|---|
| 电脑端（Go 1.20 编译）启动 | 正常 |
| WiFi 扫码配对、局域网连接、重启后自动重连 | 正常 |
| 截图、命令、中文文件读写、键盘输入中文、回收站 | 正常 |
| 控件树：任务栏、记事本文字、菜单勾选状态、保存对话框 | 正常（标题栏「关闭」按钮见下） |
| 读取 docx、旧版 xls、加密 PDF（含共享文件夹里的文件） | 正常 |
| 远程桌面推流和点击 | 正常，虚拟机里只有 2–6 帧/秒 |
| USB：装 Google 驱动后识别手机、自动启动手机端并连接 | 正常（adb 33.0.3） |
| 电脑端界面「安装驱动」：检测到缺驱动的手机，一键装上自带驱动后自动连接 | 正常（这台虚拟机关闭了 UAC，UAC 确认窗口未测） |
| 电脑端界面（Electron 22）：状态、计时、红框、顶部悬浮条、断开按钮 | 正常（修复后，见下） |
| 32 位系统 | 未测（没有 32 位镜像，32 位系统已很少见，不再测试） |
| 开启 Aero 时的红框 | 未测 |

测出并已修复的问题：

- **adb 版本**：37.x 调用了 Win8 才有的 `WaitOnAddress`，在 Win7 上直接启动失败（`0xc0000139`）。34.0.5 能启动，但生成随机数用的是 Win10 才有的 `ProcessPrng`，生成密钥、和手机认证时都会崩溃。33.0.3 用的是 `RtlGenRandom`，Win7 上一切正常。Win10 上也验证过 33.0.3 的 USB 连接。以后升级 adb 前，先用 `strings adb.exe | grep ProcessPrng` 和导入表检查。
- **控件树点击标题栏「关闭」**：Win7 的标题栏按钮声称支持 Invoke，调用却失败。现在一种点击方式失败会换下一种（DoDefaultAction）。
- **电脑端界面卡死（未响应）**：手机一连上，界面要显示全屏透明的红框窗口，用 GPU 绘制时主进程卡死。Win7/8 上改为软件绘制（`app.disableHardwareAcceleration()`）。

没打补丁的纯净 Win7 可能没有 UCRT（KB2999226），adb 33 会因缺少 `api-ms-win-crt-*.dll` 无法运行。
现在安装包在 adb 旁边自带了微软可再发行的 UCRT（来源和许可见 desktop/vendor/README.md），Win7 上实测 adb 加载的是自带的副本，Win10 上也复测正常。
这种情况下电脑端界面会在「Android 驱动 未就绪」下面说明原因和处理办法（adb 因缺少 DLL、缺少系统函数或文件损坏而无法启动时都会提示）。
已在 Win7 上拿掉 adb 的一个 DLL 模拟验证过提示。

以上 adb 和 UCRT 的结论是当时的记录：新版电脑端自己实现了 ADB 连接，不再带 adb 和 UCRT（见第 4 节），Win7 上的直连还没测。

## 2. 银河麒麟虚拟机（x86_64）

> arm64 版麒麟需要 ARM 电脑或 QEMU 模拟（很慢），建议优先在 x86_64 虚拟机上测试，arm64 等有实机再测。

### 2.1 需要下载的文件

| 文件 | 网址 |
|---|---|
| 银河麒麟桌面版 V10 安装镜像 | 麒麟软件官网 https://www.kylinos.cn/ （需要注册申请试用版） |
| adb（Linux 版） | https://dl.google.com/android/repository/platform-tools-latest-linux.zip |

### 2.2 存放位置

```
~/p2d-test/
├── p2d-core                ← 仓库 dist/core/linux-amd64/p2d-core
└── vendor/
    ├── adb/adb             ← platform-tools 中的 adb
    └── app/p2d.apk
```

### 2.3 测试步骤

1. 登录时选择 X11（Xorg）会话。Wayland 会话下截图和键鼠暂不支持。
2. 一般不需要 udev 规则（V10 SP1 上普通用户能直接访问手机，见 2.4）。如果 adb 提示 `no permissions`，再加规则：

   ```bash
   echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="2717", MODE="0666"' | sudo tee /etc/udev/rules.d/51-android.rules
   sudo udevadm control --reload-rules
   ```

   `2717` 是小米的厂商 ID，其他品牌用 `lsusb` 查看手机那一行 `ID xxxx:yyyy` 中的 `xxxx`。

3. 运行：

   ```bash
   cd ~/p2d-test && chmod +x p2d-core vendor/adb/adb && ./p2d-core
   ```

4. 如果麒麟安全中心提示「未授权的程序」，在「安全中心 → 应用执行控制」里允许 `p2d-core` 和 `adb`。
5. 其余步骤与 Win7 相同。重点记录：
   - 截图是否正常（X11）；
   - 键盘输入中文是否正常；
   - 回收站删除后，在文件管理器里能否看到并还原。

### 2.4 测试结果（2026年11月23日，银河麒麟 V10 SP1 x86_64 虚拟机，一加 13）

系统：glibc 2.31，X11（UKUI），自带 libfuse2；KySec 执行控制、联网控制为「警告」模式；预装了 adb 8.1（1.0.39）。

| 项目 | 结果 |
|---|---|
| 数据线：识别手机（普通用户，不装 udev 规则）、自动拉起手机端、连接、自动配对 WiFi | 正常（内置 adb 33.0.3） |
| 同上，改用麒麟自带的 adb 8.1 | 正常（arm64 版内置的就是这个版本） |
| 远程桌面推流 | 正常，24 帧/秒 |
| 鼠标点击定位、键盘输入中英文 | 正常 |
| WiFi 连接 | 默认被麒麟防火墙挡住，已加一键放行（见下） |

测出并已处理的问题：

- **麒麟防火墙**：`kylin-firewall` 的公用、专用模式默认都拒绝所有入站连接，手机连不上局域网端口 39272。电脑端用 `kylin-firewall -S / -g`（不需要权限）检测，界面「WiFi 直连」显示「被防火墙拦截」和「放行」按钮，点了用 `pkexec` 弹出密码框添加规则。
- **KySec 执行控制**：不认识的程序（自己拷进来的、AppImage 解压出来的）运行前要用户允许，「严格」模式下直接拒绝；dpkg 安装的程序会加入白名单。所以麒麟用 `.deb` 交付。
- **虚拟机网络**：NAT 模式下本机连不上虚拟机，改成桥接。麒麟的 sshd 默认禁止端口转发（`PermitOpen none`），远程调试时注意。

各 CPU 版本（见 DEV.md「麒麟各 CPU」）：x86_64、arm64 用上游 Electron 22 和 Go；龙芯（2026年11月起不做）和申威（sw64）不支持。arm64 没有真机实测。

## 3. 免调试连接（AOA）

### 3.1 测试结果（2026年11月24日，银河麒麟 V10 SP1 x86_64 虚拟机，一加 13 PJZ110 / Android 17）

手机关掉 USB 调试，经 VMware USB 直通连进虚拟机；电脑端以普通用户运行，装了 deb 里的 udev 规则（麒麟自带的 libmtp 规则已让登录用户能访问 MTP 手机，但不覆盖切换后的 `18D1:2D00`）。

| 项目 | 结果 |
|---|---|
| 插上没开调试的手机 | 正常：GET_PROTOCOL 探测成功，界面显示「可以免调试连接」 |
| 点「免调试连接」 | 正常：约 2 秒后手机以 `18D1:2D00` 重新出现，电脑端打开配件接口；手机上点「用 P2D 打开」后 20 秒内握手、建立会话、同步权限 |
| 虚拟桌面 24 帧/秒、宽 1280；Agent 执行命令 | 正常 |
| 拔线 | 正常：手机 4 秒内改用 WiFi 连接 |
| 插回 | 正常：电脑端记得这台手机，自动切换；勾过「默认」后手机不再弹窗，3 秒内握手并切回数据线 |
| 电脑端退出再打开（线不拔） | 正常：同一秒内重新握手连上 |
| 电脑端点「断开」 | 正常：拔线前不再连接 |
| 发图片「保存到桌面」、Agent 执行中点「停止」 | 正常（这次测试中发现并修好，见下） |

测出并已处理的问题：

- **发来的图片没法放到电脑上**：图片只发给了模型，Agent 拿不到文件，只能在电脑上到处找。图片仍然默认只给模型看（不往电脑上存文件），新增 `save_attachment_to_pc` 工具：用户说「保存到桌面」等时 Agent 才把图片传到电脑，再复制到目标位置。
- **「停止」要等电脑上正在执行的命令跑完才生效**：手机端没把停止信号传给电脑端工具调用，电脑端也忽略 `notifications/cancelled`。现在手机端立即返回并发取消通知，电脑端结束命令及其子进程。
- **adb 的提示行被当成设备**：Agent 在电脑上执行 `adb devices` 时，「adb server version … killing」被解析成一台叫 adb 的设备。
- 拔线、切换 USB 调试的瞬间会收到几段被截断的数据，日志改为每条链路只记一次。
- 测试时注意：手机开着 USB 调试连上电脑时，电脑端会用内置安装包覆盖手机上的 App，内置包要和测试的版本一致。

### 3.2 还没测的

| 项目 | 期望 |
|---|---|
| 手机没装 App 时点「免调试连接」 | 手机提示打开下载页；电脑端停在「请在手机上打开 P2D」 |
| 用 tar.gz 解压运行（没有 udev 规则） | 提示「没有权限访问这台手机的 USB 设备」 |
| 手机开着 USB 调试 | 走 USB 调试连接（电脑端自己实现的 ADB，见第 4 节） |
| 锁屏状态下点「免调试连接」 | 部分手机不切换，10 秒后提示解锁后重试 |
| 其他品牌手机（小米、华为 / 荣耀、vivo） | 支持配件模式的都能连 |
| arm64 真机 | 没有真机 |

## 4. 电脑端自己实现的 ADB 连接（不带 adb）

### 4.1 测试结果（2026年11月25日，Windows 10 x64，一加 13 PJZ110，ADB 接口驱动是一加的 WinUSB 驱动）

| 项目 | 结果 |
|---|---|
| 按设备接口 GUID 找到手机，取到 USB 序列号 | 正常 |
| 握手：用已有的 `~/.android/adbkey` 签名，手机直接通过（以前点过「一律允许」） | 正常，约 5 毫秒 |
| 公钥格式：用 adbkey 算出的公钥和 adb 生成的 adbkey.pub 一致 | 正常 |
| 执行命令（getprop、pm path、带特殊字符的参数） | 正常 |
| 大量输出：3 MB | 正常，约 140 毫秒 |
| 安装 60 MB 的 APK（`cmd package install -S`） | 正常，约 2.8 秒 |
| reverse 建立、列出、删除 | 正常 |
| 电脑端完整流程：发现手机、拉起手机端、经隧道连上、会话保持 | 正常 |
| 电脑上已有 adb 服务占着手机：经 5037 端口连接 | 正常 |
| 关掉那个 adb 服务：3 秒内自动改为直连 | 正常 |
| 连续 8 次断开重连 | 正常 |

测出并已修复的问题：

- **大量输出卡住**：每次读 16 KB、不管消息边界时，第二条 256 KB 的消息收不全就停了。改成和 adb 一样按消息读：消息头读 24 字节，数据按长度读。
- **打开时复位端点（WinUsb_ResetPipe）反而让手机断开重连**：去掉了。

### 4.2 还没测的

| 项目 | 期望 |
|---|---|
| 第一次连接（手机没允许过这台电脑的密钥） | 手机弹出「允许 USB 调试吗？」，电脑端显示「请在手机上点允许」，点了以后自动继续 |
| 麒麟（Linux usbfs）：开了 USB 调试的手机 | 和 Windows 相同；没有 udev 规则（tar.gz 解压运行）时提示没有权限 |
| 麒麟 arm64 | 和 x86_64 相同（以前 arm64 用麒麟源里的 adb） |
| Win7（项目自带的 WinUSB 驱动描述文件）、32 位 Windows | 和 Win10 相同 |
| 手机装了厂商自己的非 WinUSB 驱动（如三星） | 提示驱动不是 WinUSB；电脑上有 adb 服务时经它连接 |

## 5. 改名为 P2D、平板触控模式（Windows 10 x64，一加 13 PJZ110）

### 5.1 测试结果（2026年11月25日，CI 构建 0.1.0-ci.31）

| 项目 | 结果 |
|---|---|
| 安装包文件名 `P2D-<版本>-win-x64-setup.exe` | 正常 |
| 静默覆盖安装到旧版目录（`/S /D=<目录>`） | 正常：旧进程被结束，程序改名为 `P2D.exe` |
| 开机自启 | 正常：Run 项 `p2d` 自动改指向 `P2D.exe`，仍带 `--hidden` |
| 数据目录、配对记录 | 正常：仍在 `%APPDATA%\p2d`，手机立即用原配对经 WiFi 连上 |
| 手机端自动更新 | 正常：检测到版本不同，经 USB 装上正式签名的新 APK，自动拉起后经数据线连上（第一次重连时手机还用旧令牌，被拒一次后自动换新令牌） |
| 电脑上开着 adb 服务时经 5037 端口连接、关掉后改回直连 | 正常 |

平板触控模式分两层测：

- 手势控制器 → 真实的 Core → 这台电脑的鼠标：在 Node 里给 `RemoteController` 喂模拟的触摸事件（含双指），用记事本窗口当靶子，检查窗口位置、是否最大化、右键菜单、鼠标位置。
- 真机：在一加 13 的虚拟桌面上用 `adb shell input` 模拟单指操作（adb 不能模拟双指）。

| 手势 | 模拟（含双指） | 真机（adb） |
|---|---|---|
| 轻点 | 鼠标落在目标上（误差 0） | 点在 (749,481)，预期 (750,480) |
| 按住拖动标题栏 | 窗口移动 392,196，和预期一致 | 窗口移动 238,119，预期约 237,118 |
| 点两下标题栏 | 窗口最大化 | 窗口最大化 |
| 长按 | 弹出右键菜单 | 弹出右键菜单 |
| 双指轻点 | 弹出右键菜单 | — |
| 双指上滑 | 滚动 4 格，方向和手机上滑列表一致 | — |

## 7. 分块推流（Windows 10 x64，2560×1600，150% 缩放）

### 7.1 测试结果（2026年11月26日，本地编译的 Core + Node 里模拟手机收块、回确认）

改动起因：一加 13 上看虚拟桌面画面糊、帧率低。原因是画面缩到 1280 宽（只有一半清晰度），每帧整屏 JPEG 转 base64，手机用 React Native 的 Image 解码跟不上。

| 项目 | 结果 |
|---|---|
| 第一帧 | 整屏 70 块（2560×1600 原分辨率），457 KB，开始推流后 46 毫秒到达，块拼起来正好盖满画面 |
| 电脑端每帧耗时 | 截屏 22–32 毫秒，比较加编码变化的块 3–4 毫秒（整屏 13 毫秒） |
| 动态壁纸 + 半透明窗口（上半屏一直在变） | 22 帧/秒，平均 53 KB/帧，1.5 MB/秒 |
| 模拟手机每帧画 100 毫秒 | 电脑端自动降到 9.4 帧/秒，不积压 |
| 分块编码单元测试 | 第一帧整屏、没变化不发、改一个像素只发一块、尺寸变化和 Reset 后整屏重发、多显示器子图偏移 |
| 流控单元测试 | 2 帧没确认时等待、确认后放行、旧确认不回拨、推流停止时退出 |

## 8. 显卡截屏 + 硬件视频流（Windows 10 x64，RTX 4060 笔记本，2560×1600 165Hz）

### 8.1 测试结果（2026年11月26日）

改动起因：分块推流在一加 13 上只有 23 帧/秒左右，整屏变化时每帧 355 KB。电脑端 GDI 截屏一帧 20–30 毫秒、计时器精度 15.6 毫秒，手机端 JPEG 解码也跟不上。

| 项目 | 结果 |
|---|---|
| DXGI 桌面复制截屏 | 2560×1600 一帧 3–5 毫秒，和 GDI 截的图 99% 像素一致；165Hz 屏幕最高 165 帧/秒 |
| 分块推流（修好计时器精度后，本地） | 同样画面 45 帧/秒，23 MB/秒 |
| 硬件编码（本地，NVIDIA H.264 Encoder MFT，2376×1484） | 60 帧档 57 帧/秒、8.8 Mbps；120 帧档 96 帧/秒、14 Mbps；Windows 自带解码器解回来和屏幕每通道平均差 3.2 |
| 一加 13 真机，60 帧档 | 约 56 帧/秒，画面流畅清晰；一分钟里等手机确认的帧位 1%–7% |
| 一加 13 真机，120 帧档（`P2D_VIDEO_FPS=120`） | 拖动窗口时手机显示约 80 帧/秒；等手机确认的帧位约 6%，帧数受电脑画面实际变化次数限制，不是手机解码 |
| 发现并修掉的问题 | 电脑端推视频时回复里 `tiles` 为 false，手机端当成旧版电脑端又改成整帧推流；码率自适应按循环次数算等待，一分钟内码率掉到最低 1.5 Mbps |

### 8.2 还没测的

| 项目 | 期望 |
|---|---|
| 手机端按屏幕刷新率请求 120 帧（新 APK） | 一加 13 请求 120 帧，60Hz 屏幕的手机请求 60 帧 |
