# P2D（暂定名）技术方案与开发计划

> 目标：手机通过 **USB 数据线** 连接电脑，由手机上的 AI Agent 操作电脑（执行命令、读写文件、看屏幕、控鼠标键盘）。
> 电脑端无网络、无 WiFi、无蓝牙也能用；桌面端为**免安装、不依赖系统组件**的可执行文件。

- 编写日期：2026年11月20日
- 状态：方案评审稿（待确认「第 9 节 待确认问题」后进入开发）

---

## 1. 需求拆解

| 维度 | 要求 | 方案要点 |
|---|---|---|
| 桌面端平台 | Windows 7 SP1+（兼容到 Win10/11）、银河麒麟 V10（Linux） | 麒麟需区分 CPU：x86_64 / arm64（飞腾、鲲鹏）/ loongarch64（龙芯） |
| 运行方式 | 可执行文件、绿色免安装、不依赖系统文件 | 所有依赖（adb、驱动、运行时）全部打包进程序目录 |
| 连接方式 | 电脑无网络、无 WiFi、无蓝牙 | **只走 USB**：Android 用 ADB 隧道，iOS 用 usbmux 隧道 |
| 驱动 | 预存 ADB 驱动 | Win7 内置通用 WinUSB 驱动一键安装；Linux 内置 udev 规则 |
| 手机端 | Android + iOS 双端 App | Agent 在手机上运行（手机有流量/WiFi，可调用大模型） |
| 能力 | 命令、查看/修改文件、看屏幕、鼠标键盘 | 电脑端暴露一组「工具」，手机 Agent 通过工具调用操作 |

**核心思路**：电脑是"手脚"，手机是"大脑"。电脑上不需要任何网络和大模型，所有 AI 推理在手机侧完成（手机联网调用云端模型，或使用端侧小模型），通过 USB 下发工具指令到电脑执行。

## 2. 总体架构

```
┌──────────────────── 手机 App（Android / iOS）────────────────────┐
│  ┌──────────────┐   ┌────────────────┐   ┌──────────────────┐    │
│  │ Agent 对话    │   │ 远程桌面（手动）  │   │ 设置（权限 / 模型） │    │
│  └──────┬───────┘   └───────┬────────┘   └────────┬─────────┘    │
│         │  LLM 调用（手机自身网络）│                     │              │
│  ┌──────▼──────────────────────▼─────────────────────▼──────────┐ │
│  │       协议层：WebSocket + JSON-RPC 2.0 + 二进制帧（截图/文件）   │ │
│  └───────────────────────────────┬─────────────────────────────┘ │
└──────────────────────────────────┼───────────────────────────────┘
                    USB 数据线      │  Android: adb reverse tcp:39271
                  （不经过任何网络） │  iOS:     usbmux → 手机端口 39271
┌──────────────────────────────────▼───────────────────────────────┐
│ 电脑端（单目录绿色版）                                              │
│  ┌──────────────────────┐    本机回环    ┌──────────────────────┐  │
│  │ GUI 外壳（Electron 22）│ ◄──────────► │ Core 核心服务（Go 1.20）│  │
│  │ React + shadcn/ui     │   127.0.0.1   │ · 设备发现 / 隧道管理   │  │
│  │ 连接状态、断开          │               │ · 工具执行（见第 4 节）  │  │
│  └──────────────────────┘               │ · 自动连接 / 权限校验     │  │
│                                         └───────┬──────────────┘  │
│  内置：adb、WinUSB 驱动安装器、Apple 驱动离线包、usbmuxd、udev 规则       │
└───────────────────────────────────────────────────────────────────┘
```

### 2.1 为什么这么分层

- **Core 用 Go 1.20**：Go 1.20 是最后一个官方支持 Win7 的版本；可交叉编译出 `windows/386`、`windows/amd64`、`linux/amd64`、`linux/arm64`、`linux/loong64` 的**静态单文件**，不依赖系统 DLL / glibc 版本问题小。
- **GUI 与 Core 分离**：Core 可以无界面独立运行（服务模式/托盘模式），GUI 崩了不影响连接；龙芯等 Electron 不好支持的平台，可以退化为「Core + 系统浏览器打开本地页面」。
- **手机做大脑**：电脑完全离线也能用；模型 Key 只存在手机上，电脑上不留敏感信息。

## 3. 技术选型

### 3.1 桌面端

| 模块 | 选型 | 说明 |
|---|---|---|
| 核心服务 | **Go 1.20.x** | 最后支持 Win7 的 Go 版本；纯 Go + 少量 syscall，`CGO_ENABLED=0` 优先 |
| GUI 外壳 | **Electron 22.3.x**（Chromium 108） | Electron 22 是最后支持 Win7 的版本；同时有 linux x64 / arm64 构建 |
| UI 框架 | React 18 + **Tailwind CSS v3** + **shadcn/ui（HSL 主题版）** | ⚠️ 见 3.3 兼容性说明 |
| 打包 | electron-builder → `nsis` 安装程序（Win，默认装到当前用户目录）/ `AppImage` + `deb`（Linux） | 不需要管理员（驱动安装、为所有用户安装除外）；最初用便携版，因每次解压到临时目录容易被杀毒软件删掉服务程序，改成安装程序 |
| 龙芯 loong64 | Core + 内置轻量 Web 页面，用系统自带浏览器打开 | 或使用龙芯社区 Electron 构建（需验证） |

> 备选：如果对体积敏感（Electron 约 80~100MB），可改用 Qt 5.15 原生界面，但就无法使用 shadcn/ui 风格了。**推荐 Electron 22 方案**，界面可以做得最好看，且与手机端共享设计语言。

### 3.2 手机端

| 模块 | 选型 | 说明 |
|---|---|---|
| 框架 | **React Native（Expo bare workflow）** | 一套 TS 代码出 Android + iOS，与桌面端共享协议类型、Agent 逻辑 |
| UI | **NativeWind + react-native-reusables**（shadcn/ui 的 RN 移植版） | 与桌面端视觉统一 |
| Agent | 自研 Agent 循环（工具调用 / Function Calling） | 统一使用 OpenAI 协议；预设 OpenAI、DeepSeek，另可自定义任意兼容服务（见 4.5） |
| OCR | Android: ML Kit 离线中文；iOS: Vision 框架 | 在手机侧识别截图文字，辅助 Agent 定位 |
| 本地存储 | MMKV + SQLite | 会话历史、已连接电脑记录、MCP / Skill 配置 |
| MCP 客户端 | `@modelcontextprotocol/sdk`（TS） | 支持 Streamable HTTP / SSE；RN 需用 `expo/fetch` 才能流式读取响应 |
| Skill 解析 | 自研（解析 `SKILL.md` 的 YAML frontmatter） | 兼容 Anthropic Agent Skills 目录格式 |

### 3.3 shadcn/ui 能不能用？——**可以，但要注意版本**

| 端 | 结论 | 注意事项 |
|---|---|---|
| 桌面端（Electron 22 / Chromium 108） | ✅ 可以 | 最新 shadcn 默认用 **Tailwind v4 + `oklch()` 颜色**，需要 Chromium 111+，**Win7 上的 Chromium 108 不支持**。必须使用 shadcn 的 **Tailwind v3 + HSL 颜色变量** 版本组件，避免 `color-mix()`、`@property`、`:has()` 等新特性。 |
| 手机端 | ✅ 可以 | 使用 react-native-reusables，组件 API 与 shadcn 基本一致 |
| 龙芯浏览器退化模式 | ✅ 可以 | 同一套前端构建产物，目标浏览器设为 Chrome 87+/Firefox 78+ |

## 4. 电脑端提供给 Agent 的工具（Tool）

### 4.1 用户要求的基础能力

> 本节用 `fs.read` 这样的写法方便阅读。代码中的实际工具名用下划线（如 `fs_read`），以兼容 OpenAI / DeepSeek 的函数名规则，以 [PROTOCOL.md](PROTOCOL.md) 为准。

| 类别 | 工具 | Windows 7 实现 | 麒麟 Linux 实现 |
|---|---|---|---|
| 命令 | `shell.exec` 执行命令（支持超时、工作目录、流式输出） | cmd / PowerShell 2.0 | bash |
| 命令 | `shell.session` 持久终端会话（交互式） | ConPTY 不支持 Win7 → 用管道模式 | PTY |
| 文件 | `fs.list` / `fs.stat` / `fs.read`（分页读取、编码自动识别 GBK/UTF-8） | 纯 Go | 纯 Go |
| 文件 | `fs.write` / `fs.edit`（按行/查找替换，返回 diff） / `fs.move` / `fs.delete`（进回收站） | 纯 Go | 纯 Go |
| 文件 | `fs.search` 文件名与内容搜索 | 纯 Go | 纯 Go |
| 屏幕 | `screen.capture` 截图（可指定显示器/区域/缩放/质量） | GDI BitBlt（DXGI 复制需要 Win8+） | X11 XShm |
| 屏幕 | `screen.stream` 实时画面（JPEG 差分帧，5~15fps） | 同上 | 同上 |
| 鼠标 | `input.mouse` 移动、单击、双击、右键、拖拽、滚轮 | SendInput | XTest |
| 键盘 | `input.keyboard` 文本输入（支持中文）、组合键 | SendInput（Unicode） | XTest + 剪贴板粘贴中文 |

### 4.2 补充的 Agent 工具（提升操作准确度）

1. **读取界面控件树**（`ui.tree` / `ui.click_element`）：Win7 用 UI Automation，麒麟用 AT-SPI。Agent 能直接"点击「确定」按钮"，不用猜坐标。
2. **截图标注**：截图时叠加网格坐标/控件编号，便于大模型定位。
3. **窗口管理**（`window.list/focus/close`）。
4. **办公文档读取**（`doc.read`）：直接提取 docx / xlsx / pptx / pdf / wps 文本。
5. **剪贴板读写**（`clipboard.get/set`）、**进程管理**（`process.list/kill`）、**系统信息**（`sys.info`）。
6. **手机 ↔ 电脑传文件**（`fs.upload/download`）：在对话里附带照片/文件，Agent 自己存到电脑；需要时把电脑文件发回手机。

> 文件管理、命令执行都交给 Agent 完成，手机端**不单独做**文件管理器和终端页面。

### 4.3 界面范围（精简）

**手机端（4 个页面 + 连接页）**
- **Agent**：对话、展示 Agent 执行的步骤、回传截图；输入框支持附件和语音。
- **远程桌面**：实时画面，触控 / 触控板两种模式，键盘输入（含中文）、右键、组合键、全屏，「交给 Agent」接手当前画面。
- **扩展**：安装、启用和管理 MCP 服务与 Skill（见 4.4）。
- **设置**：已连接电脑、**电脑权限**（只读 / 标准 / 完全控制，以及执行命令、读写文件、查看屏幕、鼠标键盘四个开关）、模型配置。
- **连接**：插线后自动连接，只显示连接状态和连过的电脑；首次使用时引导开启 USB 调试。

**电脑端（纯被控端，一个小窗口）**
- 等待连接（带驱动状态，缺驱动时可一键安装）→ 正在连接（手机没装 App 时自动安装并启动）→ 已连接（显示连接时长、断开按钮）。**无需配对**。
- 被控期间：屏幕四周红框 + 顶部悬浮条（可一键断开），主窗口最小化到托盘。
- 断开热键 `Ctrl+Alt+Q`。
- 权限只在手机上设置，电脑端负责校验执行。
- 不做操作审批、审计日志、文件快照、快捷指令。

**附带**：电脑端内置 APK，Android 手机插上后可通过 adb 直接安装 App（手机不用联网下载）。

### 4.4 MCP 与 Skill（手机端安装，供 Agent 读取和执行）

#### 统一的工具来源

Agent 看到的所有工具都按 MCP 的方式管理，分三类：

```
              ┌───────────── 手机 Agent ─────────────┐
              │   工具清单 = 下面三类合并（可单独开关）    │
              └───┬──────────────┬──────────────┬───┘
                  │              │              │
   ① 电脑（内置）  │  ② 远程 MCP   │  ③ 电脑上的 MCP │
   Core 本身就是一个 │  手机直接连接    │  stdio 进程在电脑上 │
   MCP Server，经 USB│  Streamable HTTP│  运行，Core 经 USB  │
   提供 shell/fs/    │  / SSE（走手机  │  转发给手机         │
   screen/input 等  │  自己的网络）    │  （电脑可完全离线）   │
```

| 类型 | 运行位置 | 说明 |
|---|---|---|
| ① 电脑内置工具 | 电脑 Core | 第 4.1/4.2 节的工具。Core 直接实现 MCP Server 协议，手机端像使用普通 MCP 一样调用 |
| ② 远程 MCP | 第三方服务器，手机直连 | 如联网搜索、地图、企业内部接口等。只走手机网络，**不经过电脑**，电脑仍然离线 |
| ③ 电脑上的 MCP（stdio） | 电脑本地进程 | 如数据库、本地知识库等。Core 启动该进程并通过 USB 转发。前提是电脑上有对应运行环境（Node / Python 等），否则需要提供离线安装包或单文件版 MCP |

**安装方式**（手机「扩展 → MCP → 添加」）：
- **填写地址**：URL + 可选请求头，例如 `Authorization: Bearer <YOUR_MCP_TOKEN>`。
- **粘贴 JSON**：兼容常见的 `mcpServers` 配置格式（Claude Desktop / Cursor 同款），自动识别是远程还是 stdio。
- **扫码导入**：扫描配置二维码。
- 每个 MCP 可以整体开关，也可以单独开关其中的工具。

#### Skill

Skill 采用 Anthropic Agent Skills 的目录格式：一个文件夹，里面有 `SKILL.md`（带 `name` / `description` 的 frontmatter）+ 可选的脚本、模板和参考资料。

```
excel-report/
├── SKILL.md            # 说明：什么时候用、步骤是什么
├── scripts/merge.ps1   # 可选：Windows 脚本
├── scripts/merge.sh    # 可选：麒麟脚本
└── templates/汇总模板.xlsx
```

- **按需加载**：系统提示词里只放每个 Skill 的名称和一句话描述。Agent 判断需要时才调用 `skill.read` 读取完整 `SKILL.md`，需要时再读附带文件，节省 token。
- **执行脚本**：手机上不能运行 bash / PowerShell，所以脚本在**电脑上执行**。Agent 调用 `skill.run` 后，Core 把 Skill 文件同步到电脑的缓存目录（按内容哈希缓存，只传一次），再按系统选择 `.ps1/.bat` 或 `.sh` 执行。执行受手机上「执行命令」权限开关控制。
- **安装方式**：导入 `.zip`（从手机文件、微信/QQ 收到的文件）、填写下载地址、从 Git 仓库地址导入、在 App 内新建 / 编辑 `SKILL.md`。
- **内置示例 Skill**：如 Excel 汇总、批量重命名、日志排查、系统巡检等，开箱即用。

#### 通过对话安装（直接跟 Agent 说）

除了在「扩展」页手动添加，也可以直接在 Agent 对话里装，Agent 自带一组管理扩展的工具：

| 工具 | 作用 | 对话示例 |
|---|---|---|
| `ext.install_skill` | 从对话附件（zip）、下载地址、Git 仓库安装 Skill | 「把这个 zip 装成 Skill」 |
| `ext.create_skill` | 根据描述自动写 `SKILL.md` 和脚本，生成新 Skill | 「把刚才汇总报表的步骤做成一个 Skill，以后直接用」 |
| `ext.add_mcp` | 根据地址或粘贴的 JSON 添加 MCP | 「帮我装个联网搜索 MCP，地址是 …」 |
| `ext.list` / `ext.toggle` / `ext.remove` | 查看、启用 / 停用、卸载 | 「把系统巡检那个 Skill 关掉」 |

- Agent 解析后，在对话里弹出**安装卡片**（名称、类型、包含的脚本），用户点「安装」才生效，避免模型误装。
- 需要令牌时，卡片里提供**安全输入框**，令牌直接进手机安全存储，**不会出现在聊天记录里，也不会发给大模型**。
- 刚装好的扩展在当前对话中立即可用，不需要重开对话。

#### 安全

- 安装时显示来源、包含的脚本和请求的工具，确认后才启用。
- 来自 Skill 和 MCP 的指令只作为参考资料，不能绕过手机上的电脑权限设置。
- 远程 MCP 的 Token 存在手机安全存储（Android Keystore / iOS Keychain）里，不会传到电脑。

### 4.5 大模型预设

手机「设置 → 模型」里提供三个选项，选中预设后只需填 API Key。

| 预设 | 接口地址 | 需要用户填写 | 说明 |
|---|---|---|---|
| **OpenAI** | `https://api.openai.com/v1`（官方地址，预置，界面不显示） | API Key、选择模型 | OpenAI 协议，支持工具调用和图片输入 |
| **DeepSeek** | `https://api.deepseek.com`（官方地址，预置，界面不显示） | API Key、选择模型 | 兼容 OpenAI 协议，支持工具调用。**不支持图片输入**，看屏幕时自动改用「文字识别 + 控件树」（见下文） |
| **自定义** | 用户填写 | 名称、接口地址、API Key、模型、能力开关 | 任意兼容 OpenAI 协议的服务，如通义千问、Kimi、智谱、公司自建的 vLLM / Ollama。可以保存多个 |

**实现要点**：
- **统一走 OpenAI 协议**：`POST {baseURL}/chat/completions`，开启流式输出和 `tools`。三个预设用同一套客户端，只是默认值不同。
- **模型列表自动获取**：填好 Key 后调用 `GET {baseURL}/models` 拉取可用模型供选择，拉取失败时可以手动输入。代码里不写死模型名，厂商上新模型也不用发版。
- **能力标记**：每个模型配置带两个开关：
  - `supportsVision`（支持图片）：OpenAI 预设默认开，DeepSeek 预设默认关，自定义由用户选择。
  - `supportsTools`（支持工具调用）：默认开。
- **不支持图片时的降级**：Agent 要看屏幕时，不发截图，改为发送手机端 OCR 识别出的文字和坐标，加上电脑上读到的界面控件树（`ui.tree`）。DeepSeek 也能完成大部分操作，只是对纯图形界面（图标、图片内容）的理解会弱一些。
- **测试连接**：保存前发一次最小请求，检查 Key 是否有效，以及工具调用是否可用。
- **Key 存储**：存在手机安全存储（Android Keystore / iOS Keychain），不会传到电脑。
- **对话中切换**：Agent 页顶部可以快速切换当前使用的模型配置。

## 5. USB 连接方案（核心难点）

### 5.1 Android：ADB 隧道

1. 手机开启「开发者选项 → USB 调试」，插线后在手机上允许调试授权。**这是用户唯一需要做的操作**（每台电脑一次）。
2. 电脑端 Core 每秒轮询 `adb devices`，发现授权设备后**全自动**完成：
   1. 检查手机上是否已装 App（`pm path`），没装就用内置 APK 自动安装。
   2. 建立隧道：`adb reverse tcp:39271 tcp:39271`。
   3. 生成本次连接的随机令牌，通过显式 Intent 启动 App 并把令牌传过去：`am start -n <包名>/.MainActivity --es p2d_token <令牌>`。显式 Intent 只有本 App 能收到。
3. 手机 App 带着令牌连接 `ws://127.0.0.1:39271`，流量经 USB 直达电脑 Core。
4. 不产生任何网络接口，**不会把手机网络共享给电脑**（适合内网/涉密场景的合规要求）。

**无需配对**：Android 的「允许 USB 调试」和 iPhone 的「信任此电脑」本身就是一次授权，插线即连，不再额外配对。

**Win7 驱动问题**（Win7 不会自动加载 WinUSB，各品牌手机驱动又不统一）：
- 方案 A（主推）：内置基于 **libwdi** 的「通用 ADB 驱动一键安装」，按插入手机的 VID/PID 动态生成并安装 WinUSB 驱动（Zadig 同原理），**覆盖所有品牌**，需管理员权限一次。
- 方案 B：同时预存 Google USB Driver + 华为/小米/OPPO/vivo/荣耀 官方 ADB 驱动离线包作为备选。
- 部分未打补丁的 Win7 不认 SHA-2 签名驱动 → 预存 **KB4474419 / KB4490628** 离线补丁，环境自检时提示安装。

**麒麟 Linux**：
- 无需驱动；需写入 udev 规则 `/etc/udev/rules.d/51-android.rules`（首次通过 `pkexec` 提权一次，或提示用户以 root 运行一次初始化脚本）。
- adb：已在 Go 中直接实现 ADB USB 协议（`internal/adbwire`），不再带 adb，arm64 / loong64 和 x86_64 一样能用 USB 调试连接。

### 5.2 iOS：usbmux 隧道

1. iPhone 插线后点「信任此电脑」。
2. 电脑端通过 usbmux 协议连接 iPhone 上 App 监听的端口（与 iTunes / 爱思助手同原理）。
3. **Windows**：需要 Apple Mobile Device Support 驱动 → 预存离线安装包（从 iTunes 安装包中提取）。
4. **麒麟 Linux**：内核自带 ipheth/usbmux 支持，内置静态编译的 `usbmuxd`。
5. 限制：iOS App 需保持在前台（iOS 后台会断开 socket），远程操作期间需保持 App 打开。

### 5.3 协议

- 传输：WebSocket（文本帧 JSON-RPC 2.0 + 二进制帧传截图/文件块）。
- 消息格式直接采用 **MCP**（`initialize`、`tools/list`、`tools/call` 等），从 M1 开始 Core 就是一个 MCP Server。手机端用同一套 MCP 客户端调用电脑工具和第三方 MCP。
- 安全（自动完成，用户无感知）：
  - **Android**：令牌由电脑经 adb 显式 Intent 下发（见 5.1），每次插线重新生成。手机上其他 App 即使连上本机 39271 端口，没有令牌也会被拒绝。
  - **iOS**：首次连接时自动交换密钥并记住电脑（TOFU，首次信任）。之后只接受这台电脑，不需要用户操作。
- 本机回环端口只绑定 `127.0.0.1`，并校验令牌。
- 心跳 + 断线自动重连 + 长任务可恢复。

### 5.4 USB 以外的连通方案对比

前提是电脑**没有网络、WiFi、蓝牙**。下表把可行方案都列出来，传输层统一抽象成「双向字节流」，上层协议不变，以后加新通道不影响 Agent 和界面。

| # | 方案 | 平台 | 需要额外硬件 | 手机要开 USB 调试 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|---|---|---|
| 1 | **USB · ADB 隧道** | Android | 否 | 是 | 稳定、快、不产生网络接口 | 用户要开开发者模式 | ✅ 主方案 |
| 2 | **USB · AOA 配件模式**（Android Open Accessory） | Android | 否 | **否** | 不用开开发者模式；电脑直接通过 libusb 和 App 收发数据 | 首次需装 WinUSB 驱动（与方案 1 共用安装器）；开发量比 ADB 大 | ✅ 第二期，作为免调试备选 |
| 3 | **USB · usbmux** | iOS | 否 | — | iPhone 唯一可行的 USB 直连方式 | Windows 需 Apple 驱动 | ✅ iOS 主方案 |
| 4 | **USB 网络共享**（RNDIS / NCM / iPhone 个人热点 USB） | 双端 | 否 | 否 | 系统自带，不用开开发者模式，双端都能用 | **会把手机网络共享给电脑**，电脑等于联网了，内网/涉密环境通常不允许；Win7 部分机型需要手动选 RNDIS 驱动 | ⚠️ 可选，默认关闭，开启前提示 |
| 5 | **有线网线直连** | 双端 | 手机 USB-C 转网口转接头 | 否 | 电脑有网口就行，点对点、不经过任何外网 | 需要转接头；iPhone 需支持有线网卡的转接头；要配静态 IP（程序自动处理） | 可选 |
| 6 | **电脑外接 USB 无线网卡 / 蓝牙适配器** | 双端 | USB 网卡或蓝牙棒 | 否 | 不插数据线，无线控制 | 等于给电脑加了无线能力，**多数涉密/内网规定禁止**；Win7 需预存网卡驱动 | 不建议默认支持 |
| 7 | **硬件 KVM 盒子**（HDMI 采集 + USB 模拟键鼠） | 双端 | 采集卡 + 键鼠模拟芯片（如 CH9329） | 否 | **电脑上什么都不用装**，任何系统包括 BIOS 都能控制 | 只能看画面、按键鼠，不能直接执行命令或读写文件（Agent 只能"打字"操作）；需要采购硬件 | 特殊场景备选 |
| 8 | **局域网 / 互联网中继** | 双端 | 否 | 否 | 电脑有网时最方便，可远程控制 | 依赖网络 | 电脑有网时自动可用，非主线 |

**推荐组合**：
- **Android**：ADB 隧道（方案 1）为主；第二期加 AOA（方案 2），没开 USB 调试也能用。
- **iOS**：usbmux（方案 3）。
- **电脑有网口时**：可选网线直连（方案 5）。
- **USB 网络共享（方案 4）**：仅在用户手动开启时使用。

### 5.5 是否需要 root / 管理员权限

**结论：手机不需要 root 或越狱；电脑日常使用不需要管理员。只有首次安装驱动时需要提权一次。**

| 端 | 场景 | 是否需要 | 说明 |
|---|---|---|---|
| Android | 安装、运行 App | 否 | 普通 App |
| Android | ADB 隧道连接 | **否**（不是 root） | 只需在「开发者选项」里打开 USB 调试，并点「允许」 |
| Android | AOA 连接（第二期） | 否 | 连 USB 调试都不用开 |
| iOS | 全部功能 | 否（无需越狱） | 插线后点「信任此电脑」 |
| Windows | 运行程序、命令、文件、截图、键鼠 | 否 | 以当前用户身份运行，绿色免安装 |
| Windows | **首次安装 ADB / Apple 驱动** | **需要管理员，一次** | 装好以后不再需要 |
| Windows | 操作「以管理员身份运行」的窗口、UAC 弹窗 | 需要 | Windows 不允许普通程序向管理员窗口发送键鼠（系统限制）。需要时可右键「以管理员身份运行」本程序 |
| 麒麟 Linux | 运行程序、命令、文件、截图（X11）、键鼠（XTest） | 否 | 以当前用户身份运行 |
| 麒麟 Linux | **首次写入 USB 权限规则**（udev） | **需要 root，一次** | 程序弹出系统密码框（pkexec），之后不再需要 |
| 麒麟 Linux | 麒麟安全中心「应用执行控制」拦截未签名程序 | 可能需要管理员 | 需在安全中心把本程序加入信任，或做麒麟软件适配认证与签名后免提示 |
| 两端电脑 | Agent 执行需要提权的命令（装软件、改系统配置） | 需要 | 默认以当前用户权限执行。需要 sudo / 管理员时，提示用户在电脑上自己输入密码，Agent 不保存系统密码 |

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Win7 驱动签名（SHA-2） | 驱动装不上 | 预存补丁 + libwdi 自签名方案 |
| arm64 / loong64 无官方 adb | 麒麟 ARM/龙芯无法连接 Android | 已在 Go 中自研 ADB USB 协议，不再依赖 adb |
| Electron 22 已停止维护 | 有已知安全漏洞 | 仅加载本地页面、关闭 nodeIntegration、启用 contextIsolation、禁止外链；不联网即无远程攻击面 |
| 麒麟新版本使用 Wayland | X11 截图/键鼠失效 | 优先 X11；Wayland 下走 xdg-desktop-portal / UKUI 接口，列为后续适配 |
| iOS 后台限制 / 上架审核 | iPhone 体验差或无法上架 | 要求前台使用；提供企业签/TestFlight 分发方案 |
| 手机 USB 调试需要用户手动开启 | 首次使用门槛 | App 内图文引导 + 电脑端检测提示 |
| Agent 误操作 | 删错文件、执行危险命令 | 手机端权限分级与开关 + 电脑端一键断开 / 热键 |
| 涉密/内网合规 | 手机接入可能违反单位规定 | 默认不桥接网络；**部署前请先确认单位保密管理要求** |
